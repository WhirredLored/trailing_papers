# Decisions

Every judgment call made while building PaperTrail, one line each (Architecture Law 10).

Format: `YYYY-MM-DD | <commit> | <decision> | <why>`

2026-08-27 | C01 | App scaffolded in the prompt-pack repo rather than a separate one | The pack ships as a directory handed to an agent; keeping prompts and code together keeps each commit next to the prompt that specified it.
2026-08-27 | C01 | Tailwind v4 with the CSS-first `@import 'tailwindcss'` and no tailwind.config | v4 is current, content paths are auto-detected, and one less config file to drift.
2026-08-27 | C01 | Vitest over Jest | Native ESM and TypeScript with no transform config, and it reuses the Vite resolver for the `@/` alias.
2026-08-27 | C01 | Service-role guard is a module-level `typeof window` throw, not the `server-only` package | `server-only` only trips in React Server Components; this app is Pages Router, so that package would silently pass. ESLint `no-restricted-imports` backs the runtime guard up at author time.
2026-08-27 | C01 | Existing pack README extended with a Setup section rather than replaced | The pack README is the repo's front door; C01 asked for setup steps, not a new document.
2026-08-27 | C01 | DECISIONS.md seeded with these lines rather than the header alone | C01 asked for a header-only file, but Law 10 requires a line per judgment call and this commit made six.
2026-08-27 | tooling | Supabase MCP server added at project scope, .mcp.json committed | Project scope is what Supabase documents, and project_ref is public (it is in the project URL), not a secret.
2026-08-27 | tooling | .agents/skills committed to git, .claude/skills gitignored | The symlinks Claude Code reads carry absolute paths to this checkout and break on any other machine; the vendored skill text is committed so upstream changes arrive as reviewable diffs, since skills load as instructions.
2026-09-04 | C02 | Rollup ARM64 native binary patched to redirect to @rollup/wasm-node/dist/native.js | Application Control policy blocks .node binaries; @rollup/wasm-node exposes the same parse/parseAsync/xxhash* interface rollup's native.js expects; patching is stable across npm installs via a postinstall note in BUILDLOG.
2026-09-04 | C03 | deposit_pct stored as integer 0-100, default_tax_bp as integer basis points | Consistent with Law 4 (integer math); avoids float rounding on percentages; tax displayed to user as decimal, converted on save.
2026-09-04 | C03 | Logo upload via base64 body (not multipart) | Keeps the API route simple and avoids multipart parser config across environments; 5 MB cap enforced server-side; upsert=true replaces existing logo atomically in Storage.
2026-09-04 | C03 | company-assets Storage bucket must be created manually in Supabase dashboard | Storage bucket creation requires the Management API or dashboard; it cannot be created via SQL migration; documented in BUILDLOG AWAITING HUMAN.
2026-09-04 | C04 | client/property/project tables duplicate C02 tenancy template exactly | Strict adherence to C02 template: `company_id` on every table, `deleted_at` for soft deletes, `updated_at` trigger, and explicit RLS policies (select/insert/update).
2026-09-04 | C04 | project_user linking table added | Allows many-to-many relationship for assigning team members to projects, with its own RLS policies tied to `company_id`.
2026-09-05 | C05 | Rounding rule: round half away from zero at line level, sum, then tax | Prevents double-rounding and matches standard accounting practice. Every line's extended amount is rounded once; tax is computed on the integer sum and rounded once. A single `roundHalfAwayFromZero` function is the only rounding used.
2026-09-05 | C05 | Markup and margin are explicitly separate functions | Contractors conflate "20% markup" ($120 on $100 cost) with "20% margin" ($125). Both are common and both are valid; labeling them differently prevents a 4% pricing error on every job.
2026-09-05 | C05 | Discount allocated pro-rata across taxable and non-taxable lines | When a percentage discount applies to a mixed estimate (taxable materials + exempt labor), the discount is split proportionally. The taxable share reduces the tax base. This matches standard state sales tax practice and prevents over-taxation.
2026-09-05 | C05 | parseCents uses string split, not parseFloat | Splitting on "." and parsing integer parts avoids IEEE 754 precision traps (e.g. `parseFloat("1.005") * 100 === 100.49999…`). Sub-cent input (>2 decimal places) is rounded by the single rounding rule.
2026-09-05 | C06 | catalog_item.code unique index scoped to company + non-deleted | Prevents code collision within a company but allows the same code in different companies. Soft-deleted items don't block re-use of their code.
2026-09-05 | C06 | Price history via AFTER UPDATE trigger, not application layer | Guarantees history is captured regardless of whether the update comes from the API, CSV import, bulk reprice, or direct SQL. The trigger function runs as SECURITY DEFINER so it can always insert.
2026-09-05 | C06 | Catalog items archived (soft-deleted), never hard deleted | Law 8. Items may be referenced by historical estimates and must remain for audit. Archive sets deleted_at; active flag controls whether items appear in new estimates.
2026-09-05 | C06 | Starter catalog is an explicit seed script, not auto-seeded | C06 spec: "clearly marked as sample data the contractor is expected to replace." Running `npx tsx scripts/seed-catalog.ts <company-id>` is an explicit choice; no hidden defaults.
2026-09-05 | C06 | CSV import idempotent on code column | Re-importing the same CSV updates existing items rather than creating duplicates. This makes CSV the contractor's primary bulk-edit workflow.
2026-09-05 | C06 | Bulk reprice applied per-row (not batch UPDATE) | Each row gets its own UPDATE so the price history trigger fires per item. Slower but produces a complete audit trail per the evidence chain thesis.

2026-09-08 | fix/tenancy | Isolation suite restructured into per-table describe blocks; both companies now seeded | The C04/C06 cases were appended inside an unclosed describe using bare test(), so the whole file failed collection and NO isolation test ran from C04 onward. Seeding only one company also made every "cannot read the other tenant" assertion pass vacuously against an empty table.
2026-09-08 | fix/tenancy | Isolation teardown deletes in FK order before removing users and companies | company_id FKs are `on delete restrict` and created_by references auth.users, so the previous cleanup would have silently failed once domain rows existed and leaked test data into the project on every run.
2026-09-08 | fix/types | types/supabase.ts now holds real generated types; types/db.ts wraps them as Tables/Insert/Update/Enums | The C01 placeholder (Record<string, never>) made every query return never/unknown, which is why 43 type errors accumulated and why `next build` had been failing since C04. The wrapper keeps regeneration from rippling through call sites.
2026-09-08 | fix/types | routeParam() narrows Next dynamic params instead of casting at each call site | req.query.id is genuinely string | string[] | undefined; a repeated ?id=a&id=b was being passed straight into .eq(), which builds a malformed filter. This was a latent bug, not just a type complaint.
2026-09-08 | fix/types | catalog CSV kind/unit use casts rather than type predicates | The values are validated against VALID_KINDS/VALID_UNITS immediately above, and hasErrors short-circuits before any insert, so the invariant already holds; a predicate would have meant restructuring working import logic for no runtime gain.
2026-09-08 | fix/types | catalog/index.ts kind filter casts rather than rejecting unknown values | Preserves existing behaviour exactly — Postgres still rejects an invalid enum with the same error. Filtering it out client-side would have been a silent API contract change.
2026-09-08 | chore/presentation | Build specs moved from repo root to prompts/, with an index README | 21 C-files at root dominated GitHub's file listing and made the app code read as a byproduct of the specs. Nothing imports them, so the move is inert; .prettierignore now excludes the directory rather than a root-anchored filename pattern.
2026-09-08 | chore/presentation | README rewritten to lead with the product rather than the spec pack | The previous first screen described a folder of prompts, so a reader's takeaway was "prompt collection" rather than a multi-tenant application with database-enforced isolation.
2026-09-08 | chore/presentation | BUILDLOG's applied migration hand-offs marked RESOLVED rather than deleted | A build log is a historical record; deleting the "AWAITING HUMAN" lines would erase the fact that three migrations sat unapplied for four days, which is the most instructive thing in the file.
2026-09-08 | C07 | buildDerivation now renders a per-unit rate as a division when the reciprocal is a whole number | The division branch was unreachable (guarded by quantityPerDriver >= 1, but a "per 100 sq ft" rate is 0.01), so output read "x 0.01" where the spec's worked example requires "/ 100". The spec calls the derivation string a requirement, not a nicety, so the format is now asserted verbatim in a test.
2026-09-08 | C07 | Sample assemblies extracted to lib/sample-assemblies.ts, imported by both the seed script and its tests | A known-answer test against a copy of the rates would prove nothing about what actually gets seeded. The seed script cannot be imported directly because it exits on a missing argv.
2026-09-08 | C07 | The assemblies seed creates INS-FANFOLD if absent rather than editing the C06 catalog seed | C07 must seed a backerboard assembly and the C06 catalog has no backerboard item. Editing a shipped seed would change what earlier commits produce; creating the item on demand keeps each seed self-contained.
2026-09-08 | C07 | quantity_per_driver precision kept at numeric(12,4) rather than widened | Rates finer than 4dp (a house-wrap roll covers ~1,350 sq ft) are rounded and the true coverage stated in the component note. Widening it would mean a second migration against an applied one for a rounding difference that up_to_unit absorbs anyway.
2026-09-08 | C07 | The live preview calls computeTakeoff in the browser rather than the takeoff API | The engine is pure, so the number shown while editing is produced by the same code the server validates with - there is no second implementation to drift. Nothing persists until Save.
2026-09-08 | C07 | Tests index components through a componentAt() helper instead of non-null assertions | noUncheckedIndexedAccess makes components[0] possibly undefined; the helper fails with the assembly name and length instead of a bare property-of-undefined further down.

2026-09-08 | C08 | Immutability enforced by trigger on both estimate and estimate_line, not by a status check in the API | Law 3 says enforce in the database. The trigger freezes content, money terms and totals once the estimate leaves draft, and refuses inserts, updates and deletes on the lines of a non-draft estimate — so the guarantee holds for the API, a direct PostgREST call, and a service-role script alike.
2026-09-08 | C08 | A draft can only leave 'draft' through issue_estimate(), which announces itself with a transaction-local setting | Without this, `update estimate set status='issued'` would produce an issued estimate with unfrozen totals and no PDF snapshot. The setting is the trigger's proof that the freeze actually ran.
2026-09-08 | C08 | The prior version is superseded at issue time, not when the revision is created | A revision abandoned in draft would otherwise cancel a live estimate the client is still holding. supersede is a consequence of issuing v(N+1), not of starting to edit it.
2026-09-08 | C08 | Totals are computed in TypeScript by lib/totals.ts and passed into the SQL functions as jsonb, never recomputed in SQL | A second implementation of the money in plpgsql would drift from the engine the builder and the tests use. The functions freeze what the engine produced; the route computes it from the stored lines, so nothing the client claims is trusted (Law 4).
2026-09-08 | C08 | estimate_line snapshots unit_cost_cents instead of reading the cost back through catalog_item | A bulk reprice (C06) would otherwise silently move the margin on an estimate that was already issued, and free-text lines have no catalog row to read at all.
2026-09-08 | C08 | Optional lines carry is_selected alongside is_optional | The spec lists only is_optional, but "does not count toward the total until selected" needs the selection to persist. A check constraint keeps is_selected false on non-optional lines so the pair cannot hold a meaningless state.
2026-09-08 | C08 | Hours by phase groups labour lines by group_label | The phase table does not exist until C15. Assembly takeoffs insert their components under the assembly name — which is the phase (demo, siding, trim) — so the group label already is the phase, with no speculative column.
2026-09-08 | C08 | Only hour-unit labour lines contribute hours; a day-rate line contributes cost but no hours | There is no defensible constant converting a crew day into hours, and inventing one puts a wrong number in front of someone scheduling work.
2026-09-08 | C08 | Margin is measured against pre-tax revenue (subtotal less discount) | Sales tax is collected for the state and is not the contractor's money; including it would overstate the margin on every job.
2026-09-08 | C08 | save_estimate_draft() replaces the header and all lines in one locked function | The save is a read-then-write (check draft, delete lines, insert lines, write totals). Three REST calls would let a phone that loses signal mid-save leave an estimate with no lines.
2026-09-08 | C08 | A project holds at most one open draft estimate; POST returns 409 pointing at it | Two parallel drafts on one project is how a job gets quoted twice at two different numbers.
2026-09-08 | C08 | Issue and revise require owner or admin; saving a draft does not | Issuing puts a price in front of a client and freezes it. Building the estimate is ordinary crew-visible work.
2026-09-08 | C08 | Issued estimates expire 30 days out unless a date is supplied | expires_at is in the spec with no stated default; an estimate that never expires is a price the contractor is still bound to when material costs have moved.
2026-09-08 | C08 | A catalog item's own default_markup_bp wins over the estimate rate in markup mode; margin mode always uses the estimate rate | The per-item markup is the contractor's considered rate for that item. Margin is an estimate-level pricing decision, so there is no per-item equivalent to defer to.
2026-09-08 | C08 | Lines reorder by drag AND by up/down buttons | Drag is the desktop gesture; HTML5 drag events are unreliable on a phone, which is the primary device. The buttons are the glove-friendly path, not a fallback for accessibility alone.
2026-09-08 | C08 | Retire before purge: a non-draft estimate can be hard-deleted only once deleted_at is set | An absolute delete block leaves no way to remove a record that must go (a retention request, or the fixtures a live-project test run creates). Requiring the soft delete first makes a purge two deliberate statements. There is no DELETE policy on public.estimate, so no authenticated user can reach the path at all — it is service-role only.
2026-09-08 | C08 | catalog_item.kind added to the assembly API's nested select | Takeoff-generated lines need the kind to be classified as labour for the hours-by-phase panel. Adding a column to an existing select is inert for every current caller.
2026-09-08 | C08 | Immutability proven through the service-role client, not a scoped one | The point of the acceptance case is that the trigger refuses the write even for a caller RLS does not constrain. A scoped client would pass the same assertions for the wrong reason — RLS would have stopped it before the trigger ever ran.
2026-09-08 | C08 | hookTimeout raised to 60s globally in vitest.config.ts, not per file | Seeding a tenant against the live project overruns vitest's 10s default, and a hook that times out mid-seed leaks the fixtures it already created. It bit twice: the new estimate suite, and then isolation.test.ts once the C08 seed rows pushed it over the same ceiling. A global ceiling means the next live-project suite does not have to rediscover this.
2026-09-08 | C08 | Teardown nulls the supersede pointer before deleting, then deletes highest version first | v1 points forward to v2 and v2 points back to v1, both `on delete restrict`, so neither can go first while both pointers stand. RESTRICT is checked per row rather than at end of statement, so deleting the chain in one statement does not help.
